# Πώς δουλεύει ο αυτόματος πιλότος του Θρύλου

Ο John ανοίγει την εφαρμογή και όλα είναι ενημερωμένα· δεν κάνει καμία χειροκίνητη ενέργεια.

| Τμήμα | Τι κάνει | Πού τρέχει | Συχνότητα |
|---|---|---|---|
| Live σκορ | ποδόσφαιρο, μπάσκετ, βόλεϊ, χάντμπολ από 365scores → `live-data/auto.json` + ειδοποιήσεις ntfy | GitHub Actions `live-scores` (δωρεάν) | κάθε 15′ (βρόχος ~25′ όταν υπάρχει αγώνας) |
| Τελικά σκορ | ό,τι τελείωσε (ποδόσφαιρο, μπάσκετ, βόλεϊ, χάντμπολ) γράφεται μόνιμα στο `live-data/finals.json`· η εφαρμογή το δείχνει όταν το ημερολόγιο δεν έχει ακόμη σκορ | GitHub Actions `live-scores` (`tools/finals.py`) | κάθε εκτέλεση (και χθεσινοί αγώνες) |
| Τελευταία νέα | τίτλοι + σύνδεσμοι από RSS (επίσημο site, Gazzetta, Redfreaks, SDNA, in.gr, Eurohoops, Google News κ.ά.) → `news-data/news.json` | GitHub Actions `news-feed` (`tools/news_rss.py`) | κάθε 15′ |
| Βαθμολογίες | Super League, Europa League, Euroleague, Basket League, Volley League ανδρών/γυναικών από 365scores → `news-data/standings.json` (αντικαθιστούν τον αντίστοιχο χειροκίνητο πίνακα) | GitHub Actions `news-feed` (`tools/standings_gh.py`) | κάθε ώρα |
| Εφαρμογή (PWA) | διαβάζει το auto.json ανά 20″, εμφανίζει live | GitHub Pages | συνεχώς |
| Περιεχόμενο | νέα, πρόγραμμα, αποτελέσματα, ρόστερ, αντίπαλοι, στοίχημα, βαθμολογίες, συγχρονισμός στο GitHub | ΕΝΑ Claude scheduled task «Θρύλος Daily – Αυτόματος πιλότος» με οδηγίες `docs/tasks/autopilot.md` | κάθε 2 ώρες (η ώρα 9–10 προσθέτει τα νέα, η 8 και 18 το στοίχημα) |
| Πόλο live | ο μόνος αγώνας που ΔΕΝ καλύπτει το 365scores· tracker ανά αγώνα, φτιάχνεται μόνος από τον πιλότο | Claude scheduled task «Live – …» (σβήνεται μόνο του) | ανά αγώνα πόλο |

Αλλαγή συμπεριφοράς = αλλαγή του αρχείου `docs/tasks/*.md` (το task διαβάζει πάντα την τελευταία έκδοση από το repo).
Άσχετα με τον Θρύλο (ξεχωριστά προσωπικά tasks): πρωινό email Προτάσεις ημέρας, καιρός Padel, κατάσταση Raspberry Pi.

## Τι έμαθα στις 10/11/2026 (για να μην ξαναγίνει)
- Οι προγραμματισμένες εκτελέσεις ΔΕΝ έχουν εργαλείο `add_repo` και δεν το χρειάζονται: απλό `git clone` + `tools/sync.py` κάνει push στο main (δοκιμάστηκε με ξεχωριστή εκτέλεση). Η οδηγία «add_repo πρώτα» της 8/11 έκανε τον πιλότο να γράφει στη βάση χωρίς να ανεβάζει τίποτα.
- Ο συγχρονισμός γίνεται πλέον ΠΡΩΤΟΣ και ΤΕΛΕΥΤΑΙΟΣ σε κάθε εκτέλεση, ώστε μια εκτέλεση που διακόπτεται να μην αφήνει την εφαρμογή πίσω.
- Η εφαρμογή δείχνει μόνη της πότε τα δεδομένα είναι παλιά (πορτοκαλί ένδειξη «παλιά δεδομένα», πλαίσιο στην αρχική), άρα ένα τέτοιο πρόβλημα φαίνεται αμέσως.
- `data/index.json` έχει πλέον `v` (hash ανά αρχείο): η εφαρμογή κατεβάζει μόνο ό,τι άλλαξε. Μετά από χειροκίνητη αλλαγή στο `data/`: `python3 tools/mkindex.py`.
- Chat: `docs/supabase-chat-lockdown.sql` (ανάγνωση/ανέβασμα μόνο με κωδικό) — τρέχει μία φορά στο Supabase.
