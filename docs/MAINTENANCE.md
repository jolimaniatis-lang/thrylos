# Σημειώσεις συντήρησης (audit Φάσης 4)

Κατάσταση κατά τον έλεγχο: `ui-v5`, ένα `index.html` ~1190 γραμμών (~127 KB: ~49 KB CSS, ~69 KB JS), `sw.js` 8 γραμμές.
Ό,τι ακολουθεί είναι **ευρήματα και προτάσεις· δεν έχει εφαρμοστεί αλλαγή στον κώδικα της εφαρμογής**.

## CSS
- `python3 tools/css_audit.py` βρίσκει ~79 selectors με πολλαπλό ορισμό στο ίδιο media context και 32 `!important`.
- Οι περισσότεροι ορισμοί προέκυψαν σκόπιμα από διαδοχικές φάσεις (πλοήγηση, αναγνωσιμότητα, αντίθεση, header ≤400px) και δουλεύουν ως overrides με βάση τη σειρά εφαρμογής.
- **Δεν αφαιρέθηκε τίποτα.** Μια ιδιότητα που ξαναορίζεται αργότερα στον ίδιο selector δεν είναι πάντα νεκρή: μπορεί να είναι fallback (`env()`, `dvh`, `min()`),
  να εξαρτάται από `:root[data-theme]`/`prefers-color-scheme` ή να συνδυάζεται με `!important`.
- Ασφαλής μέθοδος για το μέλλον: συγχώνευση ανά selector με οπτική σύγκριση screenshots πριν/μετά (4 πλάτη × light/dark × όλες οι καρτέλες), μία ομάδα selectors ανά commit.

## JavaScript
- Όλη η λογική σε ένα αρχείο· πολλές μακριές γραμμές (έως ~1000 χαρ.) δυσκολεύουν τα diffs.
- Τα polling intervals είναι σκόρπια αριθμητικά literals (live 15 s, υπόλοιπα 45 s, Euroleague 12 s, chat 3 s, badge 20 s). Δεν αλλάχτηκαν· ένας κοινός πίνακα σταθερών θα βοηθούσε.
- Επαναλαμβανόμενα μοτίβα: λίστες «Πηγές», κάρτες με `sec-h`, ανάγνωση/εγγραφή `localStorage` (έχουν ήδη βοηθητικά `lsGet`/`lsSet`).
- Πρόταση για μελλοντική εργασία: διαχωρισμός σε `app.css` + `app.js` (+ ES modules), ώστε να αξιοποιείται η cache του browser. Απαιτεί αλλαγή precache στο `sw.js` και δεν έγινε τώρα.

## Δεδομένα και sync
- Τεκμηρίωση σχήματος: [`DATA.md`](DATA.md)· έλεγχος: `tools/validate_data.py` (προειδοποιήσεις, όχι απόρριψη).
- `tools/sync.py`: προστέθηκαν μόνο `--dry-run` και εκτύπωση προειδοποιήσεων δομής. Η ροή (αντιγραφή, κράτημα 60 εκδόσεων, index, commit, push με retry) δεν άλλαξε.
- Γνωστοί κίνδυνοι που **δεν** αλλάχτηκαν:
  - Το push γίνεται πάντα `HEAD:main`, χωρίς έλεγχο branch — τρέχει μόνο από clone του `main`.
  - Σε αποτυχία του `git add/commit` δεν ελέγχεται ο κωδικός εξόδου.
  - Το `pull --rebase -X theirs` ευνοεί τις τοπικές αλλαγές σε conflict.
  - Το `index.json` διαβάζεται/γράφεται χωρίς ρητό encoding (ASCII σήμερα).

## Tests
- Το `tests/smoke.js` είναι ένα μεγάλο script· έχει ενότητες ανά πλάτος, touch, a11y και αξιοπιστία. Πρόταση: χωρισμός σε αρχεία ανά ενότητα όταν χρειαστεί.
- Δεν υπάρχει `package.json`· το Playwright είναι εξωτερική προϋπόθεση (βλ. README).
- Δεν υπάρχει CI. Πρόταση: GitHub Action που τρέχει `smoke.js` και `validate_data.py` σε κάθε PR (απαιτεί έγκριση, γιατί προσθέτει αρχείο workflow).
